## Get Up and Running

Follow these steps to go from zero to your first semantic query. Each step builds on the last, so you'll have a working integration in minutes.

<Steps>
  <Step title="Get your API key">
    Sign in to the dashboard at [app.bankingsemanticlayer.io](https://app.bankingsemanticlayer.io), navigate to **Settings → API Keys**, and create a new key. Copy it somewhere safe — you won't be able to view it again after closing the dialog.
  </Step>
  <Step title="Make your first API call">
    Use the SDK or a raw HTTP client to call the `/v1/entities` endpoint. This confirms your key is active and returns the canonical entity types available in your workspace.
  </Step>
  <Step title="Map your source data">
    Define a semantic mapping that connects your source system fields (e.g., `acct_no`, `bal`) to ontology properties (e.g., `bsl:accountNumber`, `bsl:balance`). Mappings are stored per source system and reused across every enrichment run.
  </Step>
  <Step title="Query semantically">
    Use the SPARQL query endpoint or the high-level fluent query API to ask questions across your standardized data — filter accounts by balance, traverse customer-to-product relationships, or pull risk-classified transactions without writing custom SQL.
  </Step>
</Steps>

## Platform Capabilities

The Banking Semantic Layer is built around six core capabilities that work together to give you consistent, trustworthy financial data.

<CardGroup cols={3}>
  <Card title="Canonical Entities" icon="building-columns" href="/core-concepts#entities">
    A shared, versioned definition of every key banking object — Customer, Account, Transaction, and Product — that all systems resolve to.
  </Card>
  <Card title="Semantic Relationships" icon="arrows-split-up-and-left" href="/core-concepts#relationships">
    Formal predicates that describe how entities connect, enabling graph traversal and intelligent inference across your data.
  </Card>
  <Card title="Taxonomy Management" icon="tags" href="/core-concepts#taxonomies">
    Hierarchical classification trees for regulatory categories, MCC codes, KYC risk tiers, and product families — applied consistently at ingestion time.
  </Card>
  <Card title="Smart Enrichment" icon="sparkles" href="/core-concepts#enrichment">
    Run raw source records through the semantic layer to produce standardized, linked, and taxonomy-labeled output ready for analytics or downstream APIs.
  </Card>
  <Card title="Compliance Ready" icon="shield-check" href="/introduction#key-benefits">
    Built-in alignment with FIBO, Basel III risk classifications, and KYC/AML taxonomies reduces the manual work of regulatory reporting.
  </Card>
  <Card title="Lineage Tracking" icon="timeline" href="/core-concepts#lineage">
    Every entity transformation is recorded with a full provenance trail so you can audit exactly where a value came from and how it changed.
  </Card>
</CardGroup>
